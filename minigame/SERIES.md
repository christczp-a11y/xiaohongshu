# 系列总纲：G-Man 教材互动模拟

2026-10-11 写，总结 01 浮力实验室、02 水循环做下来的经验。新会话做下一个模拟前先读这份，细节再查 `STYLE.md`。两份对不上时以这份为准，并顺手把 `STYLE.md` 改掉。

## 一句话
把义务教育教材里的实验和抽象概念，用 three.js 做成写实、能上手拖的 3D 小实验，打包成小红书「小工具」挂在笔记下面。账号 G-Man，人设是独立 AI 开发者，对标 PhET 的精美版。每天一个，笔记标题「Day N：模拟名」，Flag N/365。目标是让老师上课引用、家长给孩子玩，攒的是被引用，不是热点流量。

## 这系列的特点（每个新模拟都要有）
1. **一个知识点一个模拟。** 知识点按《义务教育课程标准（2022 年版）》组织，人教版只当「对应哪一课」的索引。不抄课文、插图、例题，不用人教社标识。PhET 只学交互方式，模拟全部原创。
2. **像真的。** 写实 three.js：PBR 材质、软阴影、玻璃和金属有暗边，白底上器材一眼能认出来。不能像 PhET 那样简陋，这是 Chris 最在意的差别。
3. **实验是主角。** 竖屏里 3D 区要占屏高一半以上（01 在 428×926 上是 56–63%）。界面只放用得上的东西。Chris 骂过「UI 占太多」「白白浪费位置」，空间永远先给实验。
4. **直接上手。** 打开就能玩：拖场景里的东西，数字立刻跟着变。不先读说明，不锁关卡。
5. **数字是真算的。** 读数来自物理模型，有单元测试，和课本公式对得上。为了看得见做的简化、用到的数值，写在「?」里，同时写「AI 辅助开发」。
6. **离线、小、稳。** 纯离线 zip，二三百 KB。老手机自动降画质，实在跑不动就显示静态图加要点，不白屏。
7. **一眼认出是这个系列。** 同一套石墨灰界面、立体按键、贴底白面板、粗黑体标题。

## 界面骨架（竖屏，按小红书容器定的）
这是 Chris 在 iPhone 上一条条改出来的。新模拟照抄 `sims/01-buoyancy/app/src/style.css` 和 `index.html` 的结构，不要重新设计。

- **顶部那条带**：容器在状态栏下面盖了一排圆按钮，左边返回，右边头像和分享，iPhone 上大约 CSS y 53–85。标题就放进这条带里，返回键右边一行：左边距 56px、高 32px、30px 粗黑体，右边留 100px 给两个按钮。不要为了躲按钮把整页往下挪。
- **页签**紧贴在这条带下面；「?」放在页签行最右。右上角那块不放能点的东西，会被分享键挡住。
- **中间**是 3D 场景，取景收紧到器材填满手机宽度。要读刻度的地方给一个放大镜头小窗。
- **底部**是一张贴住屏幕底边的白面板：只有上面两个圆角，Home 条的安全区算进内边距，下面不露场景。从上到下：步骤行（序号、一句话、小按钮）、选项行（标签和按钮在同一行）、四格读数、公式或图表或主按钮。面板越矮越好，01 三个页签分别约 200、270、256px 高。
- **首次提示**：深灰条放在面板第一行，先替代步骤行，第一次触摸就收起。任何浮在 3D 上的条都会挡住器材。
- **「受力分析」这类开关**贴在面板上方左边，跟着面板高度走。
- **版本号**：右下角小字「版本 月日 时:分」，温哥华时间，构建时写入。看一眼截图就知道手机上跑的是哪个包。
- **颜色**：正文 `#2b2c30`，深色键 `#44454b`，它的厚边 `#26272b`。颜色只出现在场景里。要加特别标注色先问 Chris，01 里标 F浮 的蓝 `#0071e3` 是他认可过的。

## 技术
- TypeScript + Vite + three.js 0.186，Vitest 测物理模型。字体是打包进去的 Noto Sans SC 子集（900、700 两档）。
- 两套产物：`npm run build` 出单文件网页，挂网站、双击预览用，**不能拿去上传**；`npm run minitool` 出小工具 zip，esbuild 打成 IIFE，目标 ES2017 / Chrome 61。
- 小工具规矩照官方 minitool-zip-builder 1.7.0，细节见 `STYLE.md`「小工具打包规范」：index.html 在 zip 根目录，脚本外置、经典脚本，没有网络请求和被禁 API，CSS 守 Chrome 61，WebGL 预算（DPR ≤ 1.5、draw call ≤ 100、三角形 ≤ 10 万，最低档减半），有降档和兜底。
- iOS 的安全区是页面布局之后才生效的，而且不触发 resize。凡是按 DOM 位置算的东西，比如取景、放大镜视口、贴面板的开关，要在渲染循环里定期比对，变了就重排。
- 起点：多模式、实验器材类复制 `sims/01-buoyancy/app`；单场景、按概念推进的复制 `sims/02-water-cycle/app`。02 的顶部和上面说的不一样，复制它时顶部换成 01 的。

## 做一个新模拟
1. 定知识点，写 `sims/NN-英文名/design.md`：学习目标、怎么玩、做了哪些简化、用到的数值和出处。数值要核对，不凭记忆写。
2. 复制起点 app，换场景和逻辑，界面骨架不动。
3. 跑 `npm test`、`npm run build`、`npm run minitool`。用 `?stats` 在最忙的时刻量预算。
4. 云端模拟小红书容器截图：`minigame/tools/xhs-sim.js`，用法写在文件开头。428×926 和 375×812 各看一遍，看三件事：标题没被圆按钮压住、能点的东西不在两个角、3D 区占屏高一半以上。这一步不能代替真机。
5. 按官方 skill 的清单过一遍，审计脚本对 `dist-minitool` 和 zip 各跑一次。
6. zip 文件名带版本时间，比如 `buoyancy-lab-1010-1933.zip`，放进 `/mnt/project-files/minigame/sims/NN-英文名/release/`。旧包删掉，文件夹里只留一个。同目录放 `icon.png`（1024×1024）、名称和简介（各 ≤ 14 字）。
7. 交给 Chris 时说「浏览器里验过，真机待你确认」，附版本号。他在创服平台模拟器、安卓、iPhone 各扫一次。发笔记时勾 AI 内容声明。
8. 运营按「Day N」出视频、图文、文案和标签。运营线程的东西在分支 `claude/project-thread-pyoib8` 的 `minigame/ops/`，以及共享目录 `/mnt/project-files/minigame/ops/`。

## 和 Chris 协作（10-10、10-11 踩过的坑）
- 没在他手机上看到之前，不说「修好了」。
- 一个模拟只让一个会话改、只出一个包。10-10 晚上云端会话和他电脑上的会话同时改浮力实验室，好几个包来回传，他被绕晕了。他在线程里说的话，他电脑上的会话也会收到，动手前先确认谁在改。
- 他的要求有歧义时，先用一两句复述再动手。回他只说结果，不讲过程。
- 跟他说话用他的口气：短句、口语、直接，别用文档腔。
- 参考资料（截图、帖子、文件）读不到，先想办法拿到再开工，不要边猜边做。
- 不在云端登录小红书。小红书 MCP 只在他电脑上，只用读的工具。
