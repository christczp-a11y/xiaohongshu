# G-Man 互动模拟系列：特点总览

2026-10-11 整理，给接手的新会话先读。细则都在 `STYLE.md`，这份只讲「这系列是什么、长什么样、怎么做、踩过什么坑」。

## 一句话
把义务教育教材里的知识点，用 three.js 做成**写实、能动手玩的 3D 小实验**，打包成小红书「小工具」挂在笔记下面。对标 PhET，目标是更精美、更像真的。账号 G-Man，每天一个。

上传件在各自的 `release/`。网页版是 `sims/NN/英文名.html`，双击就能打开。

## 系列的 7 个特点
1. **实验是主角**：画面要尽量大。界面只占底部一块贴边的白色面板，顶部只有一行标题。不放没用的按钮，提示不压在器材上。Chris 最在意这一条。
2. **写实微缩**：真实材质，器材放在极简白桌上，自然场景放在切面白台座上。白底下器具的轮廓要深一档。水、玻璃、地面都用着色器做细节，不靠贴图。
3. **黑白界面 + 立体按钮 + 瑞士海报版式**：石墨深灰（不用死黑），按钮有厚度、按下会沉。只有「正在发生」用深色标出来，物理量标注只用一个蓝色（F浮 用 `#0071e3`）。标题用打包进去的思源黑体。
4. **动手出结论**：直接拖、按住场景里的东西，每个动作都立刻看到读数和概念变化。不锁关卡，打开就能玩。
5. **讲得对、讲得浅**：小学高年级能看懂的短句。为了看得见做的简化要写在页面上，比如「水蒸气其实看不见」。具体数值核对过来源再用。写明「AI 辅助开发」。
6. **严格守小工具规范**：离线、外置的普通脚本（ES2017 / Chrome 61）、CSS 守老内核的基线，不用被禁的能力。用 `npm run minitool` 出 zip，过官方审计脚本。
7. **手机上跑得动、跑不动也不白屏**：每帧不超过 100 次 draw call、10 万三角形。有三档画质，按实际帧率自动降。手机不支持 3D 时显示静态图和文字讲解。

## 踩过的坑（真机才暴露，务必记住）
- **只在电脑上测不算数**。iPhone 上出过三次问题，电脑上都看不出来。改完一律让 Chris 真机扫码，看右下角 / 顶部的「版本 月日 时:分」，确认跑的是哪一次构建。
- **小红书容器的悬浮按钮**（左上返回，右上头像和分享）会压住页面顶部，而且不在安全区里，检测 `window.xhs` 在真机上也不生效。可点的东西别放进这两个角。但也**不要整条往下让**，Chris 要把空间留给实验。
- **元素自己的高度在 iPhone 首次排版时可能是 0**。贴着面板的开关要用底边去对齐面板，面板高度一变就重新排版。
- **画曲线不要「抬笔」**：快拖、低帧率时采样点会跳格，跳过的点用模型值补上，连成一整条线。
- **网页版不能拿去上传**：它的脚本是内联 module，小工具容器不执行。上传只用 `npm run minitool` 打出的 zip。
- 电脑上测试时，开着的本地预览服务器会锁住输出目录，导致 `npm run minitool` 静默失败。打包前先关掉服务器，再核对 zip 的时间。

## 每天怎么做（简版）
1. 选知识点，写 `design.md`：学习目标、交互、简化。
2. 复制对应模板的 `app/`，只换场景和逻辑，界面骨架不动。
3. `python scripts/subset-font.py` → `npm test` → `npm run build` → `npm run minitool`。用 `?stats` 在最忙的时刻量预算；跑 skill 审计脚本；手机竖屏看一遍。
4. 拷网页版和 zip 到 `sims/NN/` 和 `release/`，推 git，交给 Chris 真机验证、手动发布。宣传视频和图文卡在本机 `C:\Users\Chris\xhs\promo\`，流程见那里的 README（不在这个仓库里）。
