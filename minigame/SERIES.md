# 系列总纲：G-Man 教材互动模拟

2026-10-11 写，总结 01 浮力实验室、02 水循环做下来的经验（云端线程和 Chris 电脑上的会话各写了一版，这里合成一份）。新会话做下一个模拟前先读这份，细节再查 `STYLE.md`。两份对不上时以这份为准，并顺手把 `STYLE.md` 改掉。

## 一句话
把义务教育教材里的实验和抽象概念，用 three.js 做成写实、能上手拖的 3D 小实验，打包成小红书「小工具」挂在笔记下面。账号 G-Man，人设是独立 AI 开发者，对标 PhET，要更精美、更像真的。每天一个，笔记标题「Day N：模拟名」，Flag N/365。目标是让老师上课引用、家长给孩子玩，攒的是被引用，不是热点流量。

## 这系列的特点（每个新模拟都要有）
1. **一集做一整节。** 教材的一节做成一个模拟，用 2～3 个页签把这一节的知识点盖住（01 三页；03 补成汽油机、柴油机、能量去向三页）。这是 2026-10-11 Chris 嫌「只做了一个引擎，内容单薄」后定的，工作量约翻倍，一天一集稳不住就两天一集。知识点按《义务教育课程标准（2022 年版）》组织，人教版只当「对应哪一课」的索引。不抄课文、插图、例题，不用人教社标识。PhET 只学交互方式，模拟全部原创。
2. **实验是主角。** 竖屏里 3D 区要占屏高一半以上（01 在 428×926 上是 56–63%）。界面只有顶部一行标题、底部一块贴边的白面板。不放没用的按钮，提示不压在器材上。Chris 骂过「UI 占太多」「白白浪费位置」，这是他最在意的一条。
3. **写实微缩。** PBR 材质、软阴影。实验器材放在极简白桌上（白桌面、黑细腿、不要木纹），自然场景放在切面白台座上。白底上器具的轮廓要深一档，玻璃和金属有暗边。水、玻璃、地面的细节用着色器做，不靠贴图。不能像 PhET 那样简陋。
4. **动手出结论。** 打开就能玩：拖、按住场景里的东西，读数和概念立刻跟着变。不先读说明，不锁关卡。
5. **讲得对、讲得浅。** 读数来自物理模型，有单元测试，和课本公式对得上。文字是小学高年级能看懂的短句。为了看得见做的简化写在页面上（比如「水蒸气其实看不见」），具体数值核对过来源再用，写明「AI 辅助开发」。
6. **一眼认出是这个系列。** 石墨深灰（不用死黑）加白、立体按钮（有厚度、按下会沉）、贴底白面板、瑞士海报版式、打包进去的思源黑体标题。只有「正在发生」用深色标出来，物理量标注只用一个蓝色。
7. **严守小工具规范。** 纯离线 zip，二三百 KB。外置的普通脚本（ES2017 / Chrome 61），CSS 守老内核基线，不用被禁的能力，过官方审计脚本。
8. **跑得动，跑不动也不白屏。** 每帧不超过 100 次 draw call、10 万三角形。三档画质按实际帧率自动降；手机不支持 3D 或实在跑不动，显示静态图和文字要点。

## 界面骨架（竖屏，按小红书容器定的）
这是 Chris 在 iPhone 上一条条改出来的。新模拟照抄 `sims/01-buoyancy/app/src/style.css` 和 `index.html` 的结构，不要重新设计。

- **顶部那条带**：容器在状态栏下面盖了一排圆按钮，左边返回，右边头像和分享，iPhone 上大约 CSS y 53–85。标题就放进这条带里，返回键右边一行：左边距 56px、高 32px、30px 粗黑体，右边留 100px 给两个按钮。不要为了躲按钮把整页往下挪。
- **页签**紧贴在这条带下面；「?」放在页签行最右。右上角那块不放能点的东西，会被分享键挡住。
- **中间**是 3D 场景，取景收紧到器材填满手机宽度。要读刻度的地方给一个放大镜头小窗。
- **底部**是一张贴住屏幕底边的白面板：只有上面两个圆角，Home 条的安全区算进内边距，下面不露场景。从上到下：步骤行（序号、一句话、小按钮）、选项行（标签和按钮在同一行）、四格读数、公式或图表或主按钮。面板越矮越好，01 三个页签分别约 200、270、256px 高。
- **首次提示**：深灰条放在面板第一行，先替代步骤行，第一次触摸就收起。任何浮在 3D 上的条都会挡住器材。
- **「受力分析」这类开关**贴在面板上方左边，跟着面板高度走。
- **版本号**：右下角小字「版本 月日 时:分」，温哥华时间，构建时写入。看一眼截图就知道手机上跑的是哪个包。
- **颜色**：正文 `#2b2c30`，深色键 `#44454b`，它的厚边 `#26272b`。颜色只出现在场景里。要加特别标注色先问 Chris，01 里标 F浮 的蓝 `#0071e3` 是他认可过的。

## 技术
- TypeScript + Vite + three.js 0.186，Vitest 测物理模型。字体是打包进去的 Noto Sans SC 子集（900、700 两档），用 `app/scripts/subset-font.py` 截取。
- 两套产物：`npm run build` 出单文件网页，挂网站、双击预览用；`npm run minitool` 出小工具 zip，esbuild 打成 IIFE，目标 ES2017 / Chrome 61。
- 小工具规矩照官方 minitool-zip-builder 1.7.0，细节见 `STYLE.md`「小工具打包规范」：index.html 在 zip 根目录，脚本外置、经典脚本，没有网络请求和被禁 API，CSS 守 Chrome 61，WebGL 预算（DPR ≤ 1.5、draw call ≤ 100、三角形 ≤ 10 万，最低档减半），有降档和兜底。
- 起点：多模式、实验器材类复制 `sims/01-buoyancy/app`；单场景、按概念推进的复制 `sims/02-water-cycle/app`。02 的顶部和面板还没跟上上面的骨架，复制它时顶部和面板换成 01 的。

## 真机才暴露的坑（务必记住）
- **只在电脑上测不算数。** iPhone 上出过好几次问题，电脑上都看不出来。改完一律让 Chris 真机扫码，看右下角的版本号，确认跑的是哪一次构建。
- **容器的悬浮按钮不在安全区里**，会压住页面顶部。检测 `window.xhs` 在真机上不生效，别靠它。做法见上面「顶部那条带」。
- **iOS 的安全区是页面布局之后才生效的**，而且不触发 resize。凡是按 DOM 位置算的东西（取景、放大镜视口、贴面板的开关），要在渲染循环里定期比对，变了就重排。
- **元素自己的高度在 iPhone 首次排版时可能是 0。** 贴着面板的开关用底边去对齐面板，面板高度一变就重新排版。
- **画曲线不要「抬笔」。** 快拖、低帧率时采样点会跳格，跳过的点用模型值补上，连成一整条线，否则会画成虚线。
- **网页版不能拿去上传。** 它的脚本是内联 module，小工具容器不执行。上传只用 `npm run minitool` 打出的 zip。
- **Chris 电脑上开着本地预览服务器时，输出目录会被锁住**，`npm run minitool` 会静默失败。打包前先关服务器，再核对 zip 里的版本号。

## 每集的目录和命名
```
minigame/sims/NN-英文名/          NN 是两位编号，英文名小写加连字符，比如 02-water-cycle
  design.md                      学习目标、怎么玩、简化、数值和出处
  英文名.html                     网页版（npm run build 的 dist/index.html 拷过来）
  release/英文名.zip              小工具包（npm run minitool 的产物，改名拷过来）
  release/icon.png               1024×1024 图标
  release/上传信息.md              名称、简介（各 ≤ 14 字）、场景标签、权限、验证三项
  app/                           代码：index.html、src/、scripts/、fallback.webp、vite.config.ts
```
- 网页和 zip 用目录里的英文名（02 是 `water-cycle.html`、`water-cycle.zip`）。01 的文件叫 `buoyancy-lab`、目录叫 `01-buoyancy`，是早期留下的，不用改。01 的图标只在共享目录的 `release/` 里，仓库里还没有它的 `icon.png` 和 `上传信息.md`。
- 网址开关照 01 留着：`?mode=` 直接打开某个页签，`?pose=` 摆好姿势，`?still` 隐藏界面截静态图，`?stats` 显示 draw call 和三角形，`?tier=` 固定画质档。兜底静态图和宣传视频都靠它们。

## 做一个新模拟
1. 定知识点，写 `sims/NN-英文名/design.md`：学习目标、怎么玩、做了哪些简化、用到的数值和出处。数值要核对，不凭记忆写。
2. 复制起点 app，换场景和逻辑，界面骨架不动。
3. 截取字体，跑 `npm test`、`npm run build`、`npm run minitool`。用 `?stats` 在最忙的时刻量预算。
4. 云端模拟小红书容器截图：`minigame/tools/xhs-sim.js`，用法写在文件开头。428×926 和 375×812 各看一遍，看三件事：标题没被圆按钮压住、能点的东西不在两个角、3D 区占屏高一半以上。这一步不能代替真机。
5. 按官方 skill 的清单过一遍，审计脚本对 `dist-minitool` 和 zip 各跑一次。
6. 网页版拷成 `sims/NN-英文名/英文名.html`，zip 拷进 `sims/NN-英文名/release/`，推 git。给 Chris 的 zip 文件名带版本时间，比如 `buoyancy-lab-1010-1933.zip`，放进 `/mnt/project-files/minigame/sims/NN-英文名/release/`；旧包删掉，只留一个。同目录放 `icon.png`（1024×1024）、名称和简介（各 ≤ 14 字）。
7. 交给 Chris 时说「浏览器里验过，真机待你确认」，附版本号。他在创服平台模拟器、安卓、iPhone 各扫一次，手动发布，发笔记时勾 AI 内容声明。
8. 交接运营：新一集合进 main 就算交付，运营线程从 git 看到新一集，先玩一遍再动手。Chris 在运营线程说「Day N」，它一次出齐视频、图文、文案和标签，图上的数字要从模拟里实际读出来。宣传视频和图文卡在 Chris 电脑的 `C:\Users\Chris\xhs\promo\`，流程见那里的 README；运营线程的计划和文案在分支 `claude/project-thread-pyoib8` 的 `minigame/ops/` 和共享目录 `/mnt/project-files/minigame/ops/`。
