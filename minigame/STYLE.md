# 模拟统一规范

2026-10-10 定稿。参照实现：`sims/02-water-cycle/`。以后每天做的新模拟都按这份来；要改规范，先改这份文件。

## 形式
- 一个知识点做一个模拟，目录是 `sims/NN-英文名/`，里面放 `design.md`（设计稿）、`app/`（代码），以及打包好的离线页面 `英文名.html`（双击就能打开，也可以挂到网站上）。上传小红书用的是另一套产物，见下一节。
- 技术栈：Vite + TypeScript + three.js。网页版用 `vite-plugin-singlefile` 打包成**一个离线 HTML**。不联网、不加载 CDN，包大小 ≤ 10MB（小红书小工具的限制）。
- 竖屏优先，横屏也能用。打开就能玩，不需要先读说明。
- 小工具名称、简介各 ≤ 14 字。

## 小工具打包规范（官方 minitool-zip-builder 1.7.0，2026-10-10 读过，01、02 都按它改过）
- 上传用的包和网页版是两套产物：`npm run build` 打出单文件网页（挂网站、双击预览用；它的脚本是内联的 module，**小工具容器不认，不能拿去上传**）；`npm run minitool` 打出 `dist-minitool/` 和 zip（上传小红书用）。
- zip 根目录直接放 `index.html`，同时只允许 `.html/.css/.js/图片/字体/.json`。字体以 `.woff2` 文件放进 zip（01 放 `fonts/` 子目录，02 放根目录），用相对路径引用。
- **脚本必须外置、必须是经典脚本**：不能用内联 `<script>`，不能用 `type="module"`。由 esbuild 打成 IIFE，目标 ES2017 / Chrome 61。
- **CSS 以 Chrome 61 为基线**：
  - flex 布局不用 `gap`，改用子项 margin；grid 用 `grid-gap`。
  - 不用 `inset`、`:has()`。
  - 不用 `<dialog>`（老 WebView 没有 `showModal()`），弹层用普通 div 加遮罩。
  - 安全区用 `@supports` 包住的 `var(--safe-area-inset-*, env(...))`。
  - 新特性只能拿来做增强，不能是唯一实现。
- **WebGL 预算**：
  - DPR ≤ 1.5，画布总像素 ≤ 200 万。
  - 每帧 draw call ≤ 100、三角形 ≤ 10 万，阴影那一遍也算在内；最低档减半。
  - 用 `?stats` 看实测数字，**要在最忙的时候量**（倒水、粒子、特效都在的那一刻）。
  - 实测：02 默认 25 次 draw call、9.85 万三角形，最低档约 17 次、4.6 万；01 默认最多 81 次、4.7 万，最低档最多 45 次、2.9 万。
- **省 draw call 的做法**（01 从 300 多次降到 81 次用的就是这些）：
  - 不动的零件按材质合并成一个网格（`mergeGeometries`；有的几何带索引、有的不带时，先统一转成不带索引）。
  - 不动的物体的影子烘焙成贴图，只让会动、露在外面的物体实时投影。
  - 同一种小物件用 `InstancedMesh` 一次画完（01 的四支受力箭头只占 2 次）。
  - 画中画（放大镜头）用 `layers` 只画需要的那几件，不要把整个场景再画一遍。
  - 焦散这类装饰在最低档关掉。
- **必须有降级和兜底**：
  - 先从中档起步，3 秒里几乎每帧都在 40 帧以上，才升一次到最高档；掉帧就降，降过就不再升。
  - 帧率持续偏低就逐级降档：先降分辨率和阴影贴图，再关阴影、关透射、关装饰。
  - 计时时跳过启动和每次换档后的 1 秒，单帧超过 0.5 秒的卡顿也不算：这时候是在编译着色器，不能当成慢机。
  - 降到最低档仍低于约 12 帧，就停掉循环，显示静态图加文字讲解。
  - 设备不支持 WebGL 2、着色器编译失败时，直接显示静态图（three.js r163 起只支持 WebGL 2）。
  - 页面隐藏时停止渲染。context 丢失时停止渲染，并显示「重新打开」按钮。
  - 静态图 `fallback.webp`：用 `?still` 打开页面，隐藏界面后截图，裁剪后压到几十 KB。
- 不用网络请求、Worker、WASM、eval、剪贴板、传感器、`window.open`、外链、下载。
- **别把 `import * as THREE` 的 `THREE` 整个当成一个值来用**（比如挂到 `window` 上调试）。这样打包时没法删掉用不到的代码，包里会残留 three.js 加载器里的 `fetch()`，也就是被禁的网络请求。
- 交付前跑一遍 skill 自带的审计脚本：`python -I <skill>/scripts/audit_artifact.py dist-minitool` 和 zip 各跑一次。审计脚本只查文件，内联脚本、ES 版本、被禁 API 和 CSS 写法要自己再查一遍。
- **小红书容器的悬浮按钮**（2026-10-10 真机截图发现）：容器会在左上角放返回键、右上角放头像和分享键，盖在页面上方，安全区不包括它们。
  - 一律在安全区下面再留 40px（`--xhs-nav`，已算进 `--safe-t`），所有贴顶的东西都用 `--safe-t` 定位。不要靠检测 `window.xhs` 再加：真机上这个检测没生效。
- **页面右下角放一个很小的「版本 月日 时:分」**（构建时写入）。真机截图里能直接看出跑的是哪一次上传的包，免得拿旧包对新问题。
  - 右上角不要放可点的按钮（会被分享键挡住）。
- **竖屏底部面板贴住屏幕底边**（2026-10-10 Chris）：像底部抽屉一样，只有上面两个角是圆的，Home 条的安全区算进面板的内边距里，不要悬空留一截。面板要紧凑：按钮高 28px、读数字号 21px、图表约 74px 高，把空间让给实验画面。
- **操作提示不要挡住实验**：提示做成浅色小胶囊，和「受力分析」开关放在面板上方同一行的右边，不要压在器材中间。
- **贴着底部面板的东西（开关、提示条）要跟着面板高度走**：面板会在字体加载、换步骤后变高。不要只在启动时算一次位置，要么跟面板放在同一个容器里，要么定期检查面板高度，变了就重新排版（01 的「受力分析」开关曾被面板挡住）。
- 浏览器里跑通不算数。上传后要在创服平台模拟器、安卓真机、iOS 真机各扫码验证一次，这三步由 Chris 做。
- 发给 Chris 的上传件放在 `/mnt/project-files/minigame/sims/NN-英文名/release/`：zip、`icon.png`（目前用 1024×1024，平台的图标要求还没核实）、名称和简介。

## 画面：展台上的切面微缩
- 主体是一块真实质感的微缩场景，放在**白色哑光方台**上。场景侧面切开，露出内部（土层、结构、液体剖面）。
- 地面只显示一层很淡的影子，背景和页面融成一体。不用木纹、黄铜之类的装饰。
- 往写实方向做：PBR 材质、软阴影、环境光反射；细节纹理用代码生成，尽量不用外部贴图（包里没有图片也能做得很真，02 整包约 260KB）。
- **写实做法清单**（02 验证过，照着用）：
  - 色调映射用 `NeutralToneMapping`，曝光 1.0。AgX 会让颜色发灰，ACES 会显得卡通。
  - 环境反射用 three 的 `Sky`（物理散射天空）渲进 PMREM，跟着太阳时间刷新：静止时最多 4 次/秒，播放时约 1.5 秒一次。`scene.environmentIntensity` 控制在 0.06–0.36。白色、哑光物体（台座、云）把 `envMapIntensity` 调到 0.1–0.3，否则会被天空映成淡蓝。
  - 地面不用顶点色，改在着色器里按高度、坡度、噪声算出草地、沙滩、带层理的岩石和积雪，再用屏幕空间导数做凹凸（`look.ts` 里的 `patchTerrain`）。
  - 水：把水底高度烘焙成一张 128² 的 8 位贴图，按真实水深决定颜色和透明度（浅处透亮见底、深处深青）。岸边加泡沫，两层不同方向的波纹，水底加焦散（`makeWaterMaterial`）。
  - 植物：几何体底部压暗（简易 AO），叶面加噪声凹凸。云做成半透明柔边。
  - 物理：下落的东西按重力加速到终端速度，带上来源的水平速度；落水处出涟漪；上升的东西带一点乱流。
  - 新加效果后必须重新跑 `?stats`：阴影那一遍也算三角形，地形只接收阴影、不投射阴影。
- **颜色只出现在场景里**，界面本身不带颜色。
- **白底上要让器具跳出来**（背景长期是白色，2026-10-10 Chris 要求）：
  - 器具的外框、边缘要比背景深一档，例如测力计外壳用深灰边框，不要白配白。
  - 细小部件（指针、挂钩、刻度）要加一点暗色描边或接触阴影。
  - 玻璃器皿的边缘要做出暗边或高光，免得在白底上「消失」。
  - 判断标准：把截图缩到手机缩略图那么小，器具的轮廓仍然一眼可辨。
  - 做法参考浮力实验室：影棚环境左右放黑旗（负补光），玻璃和金属的边缘就会映出暗边。
- 实验器材类的模拟（测力计、烧杯这类）可以不做切面方台，改放在极简白桌上：白桌面、黑细腿，不要木纹。
- 昼夜、状态变化用光线和背景来表现：页面背景白天 `#f5f5f4`，夜里渐变到 `#1c1c1e`。

## 界面：白底深灰 + 立体按钮 + 瑞士海报版式
2026-10-10 第三次定稿：配色用黑白，按钮用浮力实验室那种有厚度的立体块，卡片用实心白卡，版式按瑞士海报风来。同一天晚上 Chris 觉得纯黑太死，深色统一改成石墨深灰。

- **配色**：不用纯黑。正文 `#2b2c30`，深色按钮 `#44454b`，深色按钮的厚边 `#26272b`；次要文字 `#6e6e73`，注释 `#a1a1a6`，白色按钮的厚边 `#d2d2cf`。**只有「正在发生」用深灰底白字**。需要别的特别标注色，先问 Chris。
- **按钮（立体块）**：纯色填充，圆角 11–12px，下方是一条 4px 的实色厚边。按下时整块下沉 3px。白块配浅灰厚边，深灰块配更深的灰色厚边。
- **卡片（实心白卡）**：纯白不透明，圆角 22px，下方 5px 浅灰厚边，再加一层柔和投影。卡片里的白色按钮改用浅灰 `#f4f4f2`，和卡片区分开。
- **版式（瑞士海报风）**：
  - 左上不用卡片，直接放标题：一行英文小字母（字间距加宽，右边写编号），下面一条 2px 深灰线，再下面是两行的大标题，左对齐。夜里标题变成白色。
  - 读数：左边是小字标签，右边是大号等宽数字加 %，下面一条 3px 的细进度条。
  - 概念按钮带序号（1 蒸发、2 凝结……）。只有内容本身有先后顺序时才编号。
  - 解释区：左边一个大号序号，右边是文字。控制行上方有一条细分隔线。
- **字体**：标题、页签、按钮用粗黑体 Noto Sans SC（思源黑体，SIL OFL 1.1）：标题 900，页签和按钮 700。只截取页面用到的字，改名后打包进页面，这样每部手机显示都一样（系统黑体在苹果、安卓、Windows 上字形不同）。源字体和许可在 `fonts/`，截取脚本见 `sims/01-buoyancy/app/scripts/subset-font.py`。数字和正文用系统字体。
- 固定布局：
  - 左上：海报标题。
  - 右上：读数白卡。
  - 中间：3D 场景。
  - 底部：白卡面板，从上到下依次是概念按钮、大序号加解释、控制行（滑杆 + 时间 + 播放 + 重来）、灰色小字注释（简化说明 + 「AI 辅助开发」）。
- 首次打开时，底部面板上方有一条深灰立体提示条，9 秒后或第一次操作后消失。
- **首页只放用得上的东西**（2026-10-10 Chris）：还没做完的功能不放占位按钮。底部面板尽量矮，把空间让给能动手玩的 3D 画面。
- 样式直接复制参照实现里的 `app/src/style.css`。

## 交互
- 让人直接操作场景里的东西（拖、按住、转动），不要只给按钮。
- 每个动作都要立刻看到结果，同时点亮对应的概念按钮。
- **不锁关卡**：所有场景和功能默认全部开放。

## 内容
- 解释写到小学高年级能看懂：短句，一句只说一个意思。
- 为了看得见而做的夸张或简化，要在页面上写明（例如「真实的水蒸气是看不见的」）。
- 科学说法按 `CLAUDE.md` 的规则来，不编造。涉及具体数值的，要核对可靠来源并写进 `design.md`。

## 每天的流程
1. 定知识点，写 `design.md`：学习目标、交互方式、做了哪些简化。
2. 复制起点：单一场景、按概念推进的，复制 `sims/02-water-cycle/app`；有多个模式、用实验器材的，复制 `sims/01-buoyancy/app`。界面骨架和样式不改，只换场景和逻辑。
3. 截取字体，跑 `npm test`、`npm run build` 和 `npm run minitool`，在最忙的时刻用 `?stats` 量预算，再用手机竖屏看一遍。
4. 把 `app/dist/index.html` 复制成 `sims/NN-英文名/英文名.html`，推到 git。把 zip 放进 `release/` 交给 Chris。发布到小红书由 Chris 手动完成，发布时按平台要求标注 AI 生成。
