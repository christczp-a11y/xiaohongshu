# 模拟统一规范

2026-10-10 定稿。参照实现：`sims/02-water-cycle/`。以后每天做的新模拟都按这份来；要改规范，先改这份文件。

## 形式
- 一个知识点做一个模拟，目录是 `sims/NN-英文名/`，里面放 `design.md`（设计稿）和 `app/`（代码）。
- 技术栈：Vite + TypeScript + three.js，用 `vite-plugin-singlefile` 打包成**一个离线 HTML**。不联网、不加载 CDN，包大小 ≤ 10MB（小红书小工具的限制）。同一个文件也可以直接挂到网站上。
- 竖屏优先，横屏也能用。打开就能玩，不需要先读说明。
- 小工具名称、简介各 ≤ 14 字。

## 小工具打包规范（官方 minitool-zip-builder 1.7.0，2026-10-10 读过并按它改过 02）
- 上传用的包和网页版是两套产物：`npm run build` 打出单文件网页（挂网站用）；`npm run minitool` 打出 `dist-minitool/` 和 zip（上传小红书用）。
- zip 根目录直接放 `index.html`，同时只允许 `.html/.css/.js/图片/字体/.json`。
- **脚本必须外置、必须是经典脚本**：不能用内联 `<script>`，不能用 `type="module"`。由 esbuild 打成 IIFE，目标 ES2017 / Chrome 61。
- **CSS 以 Chrome 61 为基线**：
  - flex 布局不用 `gap`，改用子项 margin；grid 用 `grid-gap`。
  - 不用 `inset`。
  - 安全区用 `@supports` 包住的 `var(--safe-area-inset-*, env(...))`。
  - 新特性只能拿来做增强，不能是唯一实现。
- **WebGL 预算**：
  - DPR ≤ 1.5，画布总像素 ≤ 200 万。
  - 每帧 draw call ≤ 100、三角形 ≤ 10 万，阴影那一遍也算在内；最低档减半。
  - 用 `?stats` 看实测数字。02 的实测是：默认 24 次 draw call、9.5 万三角形；最低档 17 次、4.6 万三角形。
- **必须有降级和兜底**：
  - 帧率持续偏低就逐级降档：先降分辨率和阴影贴图，再关阴影、换低模。
  - 降到最低档仍低于约 12 帧，就停掉循环，显示静态图加文字讲解。
  - 设备不支持 WebGL 2 时直接显示静态图（three.js r163 起只支持 WebGL 2）。
  - 页面隐藏时停止渲染。context 丢失时停止渲染，并显示「重新打开」按钮。
- 不用网络请求、Worker、WASM、eval、剪贴板、传感器、`window.open`、外链、下载。
- 交付前跑一遍 skill 自带的审计脚本：`python -I <skill>/scripts/audit_artifact.py dist-minitool` 和 zip 各跑一次。
- 浏览器里跑通不算数。上传后要在创服平台模拟器、安卓真机、iOS 真机各扫码验证一次，这三步由 Chris 做。

## 画面：展台上的切面微缩
- 主体是一块真实质感的微缩场景，放在**白色哑光方台**上。场景侧面切开，露出内部（土层、结构、液体剖面）。
- 地面只显示一层很淡的影子，背景和页面融成一体。不用木纹、黄铜之类的装饰。
- 往写实方向做：PBR 材质、AgX 色调映射、软阴影、环境光反射；细节纹理用代码生成，尽量不用外部贴图。
- **颜色只出现在场景里**，界面本身不带颜色。
- **白底上要让器具跳出来**（背景长期是白色，2026-10-10 Chris 要求）：
  - 器具的外框、边缘要比背景深一档，例如测力计外壳用深灰边框，不要白配白。
  - 细小部件（指针、挂钩、刻度）要加一点暗色描边或接触阴影。
  - 玻璃器皿的边缘要做出暗边或高光，免得在白底上「消失」。
  - 判断标准：把截图缩到手机缩略图那么小，器具的轮廓仍然一眼可辨。
- 昼夜、状态变化用光线和背景来表现：页面背景白天 `#f5f5f4`，夜里渐变到 `#1c1c1e`。

## 界面：黑白配色 + 立体按钮 + 瑞士海报版式
2026-10-10 第三次定稿：配色用黑白，按钮用浮力实验室那种有厚度的立体块，卡片用实心白卡，版式按瑞士海报风来。

- **配色**：正文和深色按钮用 `#111`/`#1d1d1f`，次要文字 `#6e6e73`，注释 `#a1a1a6`，按钮的白色块下沿用 `#d2d2cf`。**只有「正在发生」用黑底白字**。需要别的特别标注色，先问 Chris。
- **按钮（立体块）**：纯色填充，圆角 11–12px，下方是一条 4px 的实色厚边。按下时整块下沉 3px。白块配浅灰厚边，黑块配纯黑厚边。
- **卡片（实心白卡）**：纯白不透明，圆角 22px，下方 5px 浅灰厚边，再加一层柔和投影。卡片里的白色按钮改用浅灰 `#f4f4f2`，和卡片区分开。
- **版式（瑞士海报风）**：
  - 左上不用卡片，直接放标题：一行英文小字母（字间距加宽，右边写编号），下面一条 2px 黑线，再下面是两行的大标题，左对齐。夜里标题变成白色。
  - 读数：左边是小字标签，右边是大号等宽数字加 %，下面一条 3px 的细进度条。
  - 概念按钮带序号（1 蒸发、2 凝结……）。只有内容本身有先后顺序时才编号。
  - 解释区：左边一个大号序号，右边是文字。控制行上方有一条细分隔线。
- **字体**：全部用系统黑体（苹方 / 微软雅黑等）。标题字重 900，按钮 800，正文 400–500。不打包字体文件，所以不同设备上的字形会略有差别。
- 固定布局：
  - 左上：海报标题。
  - 右上：读数白卡。
  - 中间：3D 场景。
  - 底部：白卡面板，从上到下依次是概念按钮、大序号加解释、控制行（滑杆 + 时间 + 播放 + 重来）、灰色小字注释（简化说明 + 「AI 辅助开发」）。
- 首次打开时，底部面板上方有一条黑色立体提示条，9 秒后或第一次操作后消失。
- 样式直接复制参照实现里的 `app/src/style.css`。

## 交互
- 让人直接操作场景里的东西（拖、按住、转动），不要只给按钮。
- 每个动作都要立刻看到结果，同时点亮对应的概念按钮。
- **不锁关卡**：所有场景和功能默认全部开放。

## 内容
- 解释写到小学高年级能看懂：短句，一句只说一个意思。
- 为了看得见而做的夸张或简化，要在页面上写明（例如「真实的水蒸气是看不见的」）。
- 科学说法按 `CLAUDE.md` 的规则来，不编造。涉及具体数值的，要核对可靠来源并写进 `design.md`。

## 每天的流程
1. 定知识点，写 `design.md`：学习目标、交互方式、做了哪些简化。
2. 复制 `sims/02-water-cycle/app` 作为起点。界面骨架和样式不改，只换场景和逻辑。
3. 跑 `npm test`、`npm run build` 和 `npm run minitool`，再用手机竖屏看一遍。
4. 推到 git。发布到小红书由 Chris 手动完成。
